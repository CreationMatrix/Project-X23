Hello All,

The SDS ↔ DigiFSD integration is now live in Production. This release enables CSO, JOC and SDS users to move directly between customer connectivity records in SDS and the related FSD and firewall rulesets in DigiFSD.
Production date
20 November 2026
Change reference
CHG1026399826
User groups
CSO, JOC and SDS users

Business benefits

Faster investigation during incidents
SDS Portal – DigiFSD hyperlinking provides a consolidated relationship between customer connectivity and firewall controls, which helps reduce manual correlation across systems and enables faster investigation and impact assessment during cyber and operational incidents for the JOC/CSO teams.
Firewall context without leaving SDS
Provides firewall and connectivity information directly within SDS, reduces the need to switch between systems, improves usability, and supports faster access to relevant firewall configuration information.
Every rule for a customer, found faster
Enables faster identification of firewall rules associated with a customer, reduces manual searches, supports shared or multiple-FSD scenarios, and improves operational and cyber incident investigations.
 

What’s New

Move between the two systems
SDS → DigiFSD
Open the relevant FSD and firewall rules directly from the SDS Portal.
DigiFSD → SDS
Select an SDS ID in DigiFSD to open the corresponding customer page in SDS.
Link SDS IDs to firewall rules
External Client ID
Record one or more SDS IDs against firewall rules and Host Group members.
Automatic Sync via API
SDS will regularly pick up newly approved SDS ID mappings from DigiFSD.
Search by one or many SDS IDs
Search by SDS ID
Find associated FSDs and firewall rules using an SDS ID.
Multi-ID Search
Use Match Any (OR) to search several SDS IDs at once in Firewall Ruleset Page.
                    
                    
Delivery highlight
Support for External Client ID (SDS ID) against Host Group members was identified as an additional requirement late in the delivery cycle. The team successfully incorporated it within the same Production change, avoiding the need for a follow-on release.
 

Access & User Experience

Arriving from SDS Read-only access in DigiFSD. (User must be part of read only AD group GLO-CLI-SEC-AZAD-DigiFSD-RO)
No DigiFSD access Unauthorised message; no firewall data displayed
Not signed in Sign-in followed by redirection to the intended DigiFSD page

Getting Started

From SDS
Select the DigiFSD link on the relevant customer connectivity record.
From DigiFSD
Select an SDS ID on a firewall rule to open the customer page in SDS.
